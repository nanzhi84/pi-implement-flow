# 0005: Repair only published candidate defects, with continuous code provenance

Status: implemented for review; acceptance is recorded separately. Applies to Issue #6.

The controller may repair an unmerged Ticket within its approved scope. Raw command exit status or an implementation statement is never repair authority. `ReportedBehaviorFailure` is parser evidence only. The candidate gate completes independent read-only review, verifies unchanged code/contract/instructions, cleans resources, publishes the complete failure report and downloads matching raw bytes before it constructs a repairable defect. Ordinary infrastructure, invalid responses, unfinished processes and unknown writes stop. Every replacement H/C is gated and independently reviewed again.

The same integration ownership spans candidate failure, repair and regating. Resource leases cover preparation through safe cleanup/publication; activity slots cover actual commands and role sessions only. The original open PR and owned worktree are preserved. A repair append must descend from the exact remote H and use a conditional ref update; a merged M is never routed back to its old PR. M failures retain `integrated-unaccepted`; follow-up repair Tickets are a separate capability.

Progress is a change in verified results, not a count, timestamp, commit message, artifact URL or model wording. Complete previous assertion identities are retained; true assertions must not regress, and a false assertion becoming true is a comparable witness. Review blockers retain references derived from their original immutable artifact hash and index. A fresh independent review must account for every prior reference, binding resolution to a changed current blob or an actual prior-false/current-true named assertion. Missing or unverifiable evidence pauses. A run-local observed-state set can identify mechanical repetition; it is not a persistent attempt ledger. There is no repair-count or total-model-time budget.

Code evidence is a continuous sequence of Git-parent segments. Agent edit segments carry completed tool mutations and must cover every changed file, its raw-byte chain and mode. Controller merge segments independently reproduce built-in ort preparation, distinguish upstream changes from resolution writes, and have exact ordered parents `[H,B]`. Ordinary text conflicts are supported; committed attributes, custom merge behavior, nonregular files and unsupported conflict types stop. The isolated bare merge computation shares only Git objects, ignores machine merge configuration and records its Git version. Resolution changes still require complete tool-event coverage. The implementation origin never moves to erase previous writes, and segment order is not presented as a fabricated global tool sequence.

Failure reports have a distinct kind and factual passed/failed/not-run command states. They retain the approved readable context, exact versions, complete failure/review facts, code proof, cleanup and content hash. Text conflicts have H/B and a prepared tree, not a fabricated executable C. Unbounded repair does not permit discarding evidence to evade transport or context capacity; inability to preserve complete proof stops safely.

The E2E contract is in `docs/testing/t5-scenarios.md`. It uses an isolated synthetic repository, real pi/SDK/GitHub/CLI/artifacts, explicit deterministic model boundaries for repeatable defects, and real OpenAI repair/review on the normal path. An independent verifier recomputes raw Git objects rather than importing the product verifier. Historical v1 proof artifacts remain historical; no internal v1 compatibility or dual-write path is retained.
